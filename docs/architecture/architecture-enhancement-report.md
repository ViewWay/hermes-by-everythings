## 实际使用示例

### 示例 1: SaaS 项目技术栈选择

**用户输入**:
```
/hbe:architect "我需要做一个电商 SaaS，团队有 5 个人：
- 2 个 Python 后端
- 2 个 JavaScript 前端
- 1 个 DevOps
预计 3 个月上线，预算有限"
```

**HBE 分析**:
```
项目类型: Web 应用（中型）
团队技能: Python/JavaScript 混合
团队规模: 3-5 人
时间约束: 正常（3 月）
预算约束: 有限

推荐技术栈:
├─ 后端: FastAPI + SQLAlchemy + PostgreSQL
├─ 前端: Next.js + TailwindCSS + shadcn/ui
├─ 缓存: Redis
├─ 任务队列: Celery + Redis
├─ 部署: Docker Compose（本地）+ Railway（生产）
└─ 监控: Sentry + Logrocket

成本预估:
├─ 开发成本: $126,000（3 个月 × 5 人）
├─ 月运营成本: $500（10 万用户）
└─ 总首年成本: $132,000

风险:
├─ 时间压力可能需要加班
├─ 团队技能混合需要协作框架
└─ 预算有限需要使用开源方案
```

### 示例 2: CLI 工具技术栈选择

**用户输入**:
```
/hbe:architect "我需要做一个开发者工具 CLI，要求高性能、
跨平台，团队有 Go 经验，时间比较充裕"
```

**HBE 分析**:
```
项目类型: CLI 工具
团队技能: Go 专家
团队规模: 1-2 人
时间约束: 宽松
预算约束: 无明确限制

推荐技术栈:
├─ 语言: Go（最佳选择）
├─ 构建: Go 原生编译（无依赖）
├─ 测试: Go testing + testify
└─ 分发: 单文件二进制

替代方案:
├─ Rust（最高性能，但编译复杂）
└─ Python（开发快，但需要打包）

成本预估:
├─ 开发成本: $20,000（2 个月 × 1 人）
├─ 月运营成本: $0（自托管或 GitHub Releases）
└─ 总首年成本: $20,000

优势:
├─ 单文件分发，用户开箱即用
├─ 原生性能极佳
├─ 跨平台编译（Windows/Linux/macOS）
└─ 部署简单（上传二进制即可）
```

## 使用建议

### 何时使用 HBE 做架构

✅ **推荐使用**:
- 项目初期的技术栈选型
- 技术重构的框架选择
- 新产品线的架构决策
- 快速原型验证

⚠️ **需要人工介入**:
- 超大型系统（>1000 万用户）
- 特殊行业合规要求（等保 3 级）
- 极端性能要求（<10ms 延迟）

### 典型工作流

```
1. 用户: /hbe:architect "我要做一个 [项目描述]"
   
2. HBE: 
   - 分析项目类型和约束
   - 评估团队能力
   - 推荐 2-3 个技术栈方案
   - 提供成本预估
   - 列出风险
   
3. 用户: 选择方案 A
   
4. HBE:
   - 设计详细架构
   - 创建 ADR
   - 输出实施路线图
   
5. 验证: /hbe:review 架构设计
```
