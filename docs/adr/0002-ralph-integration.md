# ADR-0002: Ralph 自主循环集成

**状态**: 已接受
**创建日期**: 2026-05-02
**更新日期**: 2026-05-02

---

## 上下文

大型开发任务通常需要：
- 多次迭代（10+ 次会话）
- 跨上下文保持状态
- 自主执行无需人工干预

Claude 的上下文限制（~200K tokens）使得大型任务难以在一次会话中完成。

## 决策

集成 Ralph 自主循环系统：

**核心机制**：
1. 每次迭代 = 全新上下文起点
2. 记忆通过文件持久化（prd.json, progress.md, git history）
3. 完全自主执行，无需人工干预
4. 后台运行，实时查看进度

**流程**：
```
初始化 → 循环（选story → TDD实现 → 验证 → 提交） → 结束
```

## 理由

1. **突破上下文限制**：每次迭代重新开始，避免上下文溢出
2. **持久化记忆**：通过文件系统保持状态
3. **无人值守**：可后台运行，自动推进
4. **可恢复**：中断后可从检查点恢复

## 后果

**正面**：
- 可处理任意大小的任务
- 无需人工干预即可完成
- 进度可追踪和恢复

**负面**：
- 需要维护额外的状态文件
- 调试相对复杂
- Token 消耗可能增加

## 替代方案

1. **手动分步** - 人工多次会话
   - 缺点：耗时，易出错

2. **上下文压缩** - 压缩历史上下文
   - 缺点：可能丢失重要信息

3. **增量模式** - 只加载变更部分
   - 缺点：可能缺少必要上下文
