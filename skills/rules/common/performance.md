# Common Performance Rules

> 语言专属规则（`../<lang>/performance.md`）扩展此文件的通用性能约定。

## 核心原则

- **先测量再优化** — 不要猜瓶颈，用 profiler
- **80/20** — 20% 的代码贡献 80% 的耗时，聚焦热点
- **不要过早优化** — 可读性优先，有性能问题时再优化

## 通用策略

### 数据库
- N+1 查询是最常见瓶颈——用 join/eager loading 批量获取
- 加索引前看查询计划（EXPLAIN），不要盲加
- 分页大数据用游标（cursor）而非 offset

### 缓存
- 缓存有失效成本——不要缓存几乎不变或几乎全变的数据
- 缓存键要完整（包含影响结果的所有参数）
- 多级缓存：内存 → Redis → DB

### I/O
- 批量 > 单个（批量读、批量写）
- 异步 > 同步（不阻塞主循环）
- 流式 > 全量加载（大文件用 stream）

### 算法
- 选对数据结构比微优化算法重要（用 hash 查 O(1) vs 线性扫 O(n)）
- 避免在热路径里分配（循环内 new 对象、字符串拼接）

## 反模式
- ❌ 无测量的"优化"
- ❌ 缓存一切（失效逻辑复杂度 > 收益）
- ❌ 微优化（省 1ns 但代码可读性大降）
