# Common Patterns

> 语言专属规则（`../<lang>/patterns.md`）扩展此文件的通用设计模式约定。

## 核心原则

- **简单优先** — 不要过度设计；用最简单的能工作的方案
- **组合优于继承** — 小的、可组合的单元
- **显式优于隐式** — 让数据流和依赖可见
- **约定优于配置** — 但允许逃生舱处理边缘情况

## 常用模式

### Repository 模式
将数据访问封装在标准接口后（findAll, findById, create, update, delete）。业务逻辑依赖抽象接口，而非具体存储。

### API 响应信封
一致的响应格式：`{ success, data, error, pagination }`，让客户端解析逻辑统一。

### 配置
- 配置来自环境变量（12-factor app）
- 启动时验证配置完整性
- 有合理默认值，便于本地开发

### 错误处理
- 用结果类型或异常，不要混用
- 错误是值，可传递和处理
- 在边界（API、UI）转换错误为用户友好消息

## 反模式
- ❌ God object（一个类/模块做所有事）
- ❌ 深继承树（>3 层）
- ❌ 隐式全局状态
- ❌ 回调地狱（用 async/await）
- ❌ 重复的 switch/if-else 链（用多态或查表）
