# Common Testing Rules

> 语言专属规则（`../<lang>/testing.md`）扩展此文件的通用测试约定。

## 核心原则

- **测试驱动** — 先写测试（RED），再写实现（GREEN），然后重构（REFACTOR）
- **覆盖率 ≥ 80%** — 但覆盖率不是质量指标，断言质量才是
- **快速反馈** — 单元测试 <1s，集成测试 <30s
- **测试隔离** — 每个测试独立，不依赖执行顺序

## 测试金字塔
```
       /\
      /E2E\        少量：关键用户流程
     /------\
    /集成测试 \    中量：API、DB、服务交互
   /----------\
  /  单元测试   \  大量：函数、工具、组件
 /--------------\
```

## 测试类型
- **单元测试** — 个别函数、纯逻辑、无 I/O
- **集成测试** — API 端点、数据库操作、服务组合
- **E2E 测试** — 完整用户流程（Playwright/Cypress）

## 命名
- 测试名描述行为和预期：`shouldReturnErrorWhenInputInvalid` / `test_empty_input_returns_400`
- 避免无意义名字：`test1`、`testSuccess`

## 断言
- 每个测试一个清晰的断言点（或一组相关断言）
- 断言行为，不断言实现细节
- 失败信息清晰：什么预期、什么实际

## Mock 原则
- Mock 外部依赖（网络、DB、文件系统），不 mock 被测代码
- Mock 要真实——不要 mock 得让测试失去意义
- 优先用真实实现（in-memory DB、test server）而非 mock

## 反模式
- ❌ 测试只是为了覆盖率，无有效断言
- ❌ Mock 过度，测不到真实问题
- ❌ 测试间有隐式依赖（必须按顺序跑）
- ❌ 永远通过的测试（如 `assert true`）
