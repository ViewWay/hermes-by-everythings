# Common Coding Style

> 语言专属规则（`../<lang>/coding-style.md`）扩展此文件的通用约定。

## 核心原则

- **可读性优先** — 代码被读的次数远多于被写的次数
- **一致性** — 遵循项目既有风格，而非个人偏好（用 linter/formatter 强制）
- **小函数** — 单一职责，<50 行，<4 层嵌套
- **命名表意** — 名字说明"是什么"，注释说明"为什么"

## 通用约定

### 文件组织
- 一个文件一个主职责，典型 200-400 行，最多 800 行
- 按功能/域组织目录，而非按类型（不要 `controllers/` + `models/` + `views/` 混放无关功能）

### 命名
- 有意义、可发音、可搜索的名字
- 避免缩写（除非是领域通用术语如 `id`、`url`）
- 布尔变量用 `is/has/can/should` 前缀

### 注释
- 解释 **为什么**，不是 **是什么**（代码已说明 what）
- 保持注释与代码同步——过时注释比没有注释更糟
- 对公开 API 写文档注释

### 错误处理
- 在合适的层级处理错误（不要到处 try-catch）
- 错误消息面向人类，包含上下文（什么操作、什么输入、为什么失败）
- 永不静默吞下错误（见 silent-failure-hunter agent）

### 不可变性
- 优先不可变数据结构（创建新对象，不修改现有）
- 明确区分可变与不可变状态
