# Common Security Rules

> 语言专属规则（`../<lang>/security.md`）扩展此文件的通用安全约定。

## 核心原则

- **永不信任外部输入** — 用户输入、API 响应、文件内容、环境变量都要验证
- **最小权限** — 只授予必要的权限
- **纵深防御** — 多层防护，不依赖单一防线
- **快速失败** — 检测到安全问题立即拒绝，不要尝试"修复"恶意输入

## 输入验证
- 在系统边界（API 入口、文件读取、命令参数）验证所有输入
- 使用基于 schema 的验证（如 zod、pydantic、jsonschema）
- 验证类型、长度、范围、格式，不只是存在性

## 密钥管理
- ❌ 永不硬编码密钥（API key、password、token）
- ✅ 使用环境变量或密钥管理器
- ✅ 启动时验证所需密钥存在
- ✅ 立即轮换任何暴露的密钥

## 注入防护
- **SQL 注入**: 用参数化查询，永不字符串拼接 SQL
- **命令注入**: 避免把用户输入传给 shell；必须用时用参数数组而非字符串
- **XSS**: HTML 输出转义；CSP 头
- **路径遍历**: 验证路径在允许根目录内（`startsWith` 检查）

## 认证与授权
- 每个端点都要验证认证（不要依赖"前端会处理"）
- 每个操作都要验证授权（用户有权做这件事吗）
- 敏感操作要求重新认证

## 错误处理
- 错误消息不泄露敏感数据（堆栈、SQL、文件路径、密钥名）
- 对外返回通用错误，日志记录详细信息
- 区分"客户端错误"（4xx）和"服务端错误"（5xx）

## 速率限制
- 所有端点有速率限制
- 认证、密码重置、支付等敏感端点有更严格限制
